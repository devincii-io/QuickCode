# QuickCode packaging

This directory holds the Windows installer for QuickCode 1.0. The companion
`scripts\` directory (repo root) holds the PowerShell scripts the installer
bundles and runs.

## Files

| File | Purpose |
|---|---|
| `packaging/quickcode.iss` | Inno Setup script that builds `QuickCode-Setup-<version>.exe` |
| `packaging/quickcode.ico` | The blue ghost app icon (16/32/48/64/256), generated by `scripts/make_icons.py` |
| `packaging/setup-quickcode.ps1` | Post-install step: ensures Git/Python, builds the venv under `{app}` and pip-installs QuickCode. Bundled into the installer and run automatically. |
| `scripts/bootstrap.ps1` | Ensures Git + Python (>=3.12) are present. Reused by both scripts above in dependency-only mode. |
| `scripts/install.ps1` | Standalone local/dev installer for people who don't want the `.exe` (creates a `.venv` or uses `pipx`). |

## Option A: Build the Inno Setup installer

1. Install [Inno Setup](https://jrsoftware.org/isinfo.php) (6.x or later; the
   script uses `WizardStyle=modern`, available since 6.1).
2. From the repo root, compile the script with the Inno Setup Compiler:

   ```powershell
   & "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" packaging\quickcode.iss
   ```

   (Or open `packaging\quickcode.iss` in the Inno Setup IDE and press
   *Compile*.)
3. The compiled installer is written to
   `packaging\dist\QuickCode-Setup-<version>.exe`. That directory is
   gitignored (the repo-wide `dist/` rule).

If you changed the brand mark, regenerate the icons first — the `.iss` refers
to `packaging\quickcode.ico` for the wizard, the Add/Remove Programs entry and
every shortcut:

```powershell
uv pip install pillow          # build-time only, not a project dependency
.venv\Scripts\python.exe scripts\make_icons.py
```

### What the installer does

- Installs **per-user** by default into `%LOCALAPPDATA%\Programs\QuickCode`
  (Inno's `{autopf}` constant under `PrivilegesRequired=lowest`), with an
  option in the elevation dialog to install for all users instead.
- Copies the QuickCode source tree (enough to `pip install` it), the packaging
  scripts and `quickcode.ico` into the install directory.
- Runs `setup-quickcode.ps1` after the files are copied, which:
  - Calls `bootstrap.ps1 -SkipQuickCodeInstall` to install Git if missing (via
    `winget`, falling back to the official Git for Windows installer, silent)
    and Python 3.12 if no suitable Python (>=3.12) is on `PATH` (via `winget`,
    falling back to the python.org installer, silent, per-user).
  - Creates a private virtual environment at `{app}\venv` and installs
    QuickCode `[pty]` into it. Dependencies come from PyPI, so this step needs
    an internet connection.
  - Verifies `quickcode.exe` and `quickcode-app.exe` exist before the
    shortcuts are allowed to point at them.
- Offers three optional tasks:
  - **Add QuickCode to my PATH** (checked by default) — adds
    `{app}\venv\Scripts` to the user `PATH`, so `quickcode` and `qc` work in
    any terminal. Removed again on uninstall.
  - **Create a desktop shortcut** (unchecked by default).
  - **"Open QuickCode here" folder context menu** (unchecked by default) —
    registry entries under `HKCU\Software\Classes\Directory\...` for both the
    folder and the folder-background right-click menus, running
    `quickcode "%V"` on the clicked directory. `uninsdeletekey` removes them.
- Creates a Start Menu shortcut ("QuickCode") pointing at
  `{app}\venv\Scripts\quickcode-app.exe` with the ghost icon. That is a
  `gui-scripts` entry point, so Windows launches it through `pythonw` — the
  browser opens with no console window behind it.
- Removes `{app}\venv` and `{app}\src` on uninstall (pip and venv create files
  Inno Setup never logged and would otherwise leave behind).

Because the installer changes `PATH`, `ChangesEnvironment=yes` is set so
Explorer/new processes pick up the change without a reboot (already-open
terminals still need to be restarted).

> **Build status:** this script has *not* been test-compiled — the Inno Setup
> compiler (`ISCC.exe`) is not installed on the machine it was last edited on.
> Run the compile step above once before shipping a release.

## Option B: Local / dev install via PowerShell

If you already have this repo checked out and just want QuickCode installed
without building an installer:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install.ps1
```

By default this creates (or reuses) a `.venv` in the repo root and installs
QuickCode into it in editable mode. Useful flags:

- `-UsePipx` — install with [pipx](https://pypa.github.io/pipx/) instead,
  which puts `quickcode` on your user `PATH` globally rather than inside a
  project-local venv.
- `-Dev` — also install the `dev` extras (`pytest`, `ruff`, ...). Only
  applies to the `.venv` path.
- `-SkipDependencyCheck` — skip the Git/Python auto-install step (use when
  you already know both are present and want a faster run).

`install.ps1` calls `bootstrap.ps1` under the hood (in dependency-only mode,
`-SkipQuickCodeInstall`) to reuse the exact same Git/Python detection and
silent-install logic described above, then does its own venv/pipx install.

## Entry points

| Command | Kind | Behaviour |
|---|---|---|
| `quickcode`, `qc` | console script | Starts the local server on 127.0.0.1 and opens the browser on the current directory. `qc .` and `qc C:\proj "prompt"` also work. |
| `quickcode-app` | GUI script (`pythonw`) | Same app with the user's home directory as the default project, launched without a console window. What the shortcuts run. |

## Notes

- All scripts are written for **Windows PowerShell 5.1** (no `&&`/`||`
  chaining, no ternary/`??`/`?.` operators) since that's the default shell
  version shipped with Windows 11.
- Git and a suitable Python being already installed avoids the
  download/install paths entirely; the `pip install` step still needs the
  network to fetch QuickCode's dependencies.
- Nothing in this directory is executed as part of building/testing
  QuickCode itself; it's purely the distribution path for end users.

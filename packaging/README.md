# QuickCode packaging

This directory holds the Windows installer for QuickCode. The application it
installs is a **frozen PyInstaller onedir build**, described by
`quickcode.spec` at the repo root — so the installer copies files and does
nothing else. No Git, no Python, no venv, no network at install time.

## Files

| File | Purpose |
|---|---|
| `../quickcode.spec` | PyInstaller recipe: two executables sharing one `dist\QuickCode` folder |
| `packaging/entry_app.py` | Entry script for the windowed executable (`main_app`) |
| `packaging/entry_cli.py` | Entry script for the console executable (`main`) |
| `packaging/quickcode.iss` | Inno Setup script that wraps `dist\QuickCode` into `QuickCode-Setup-<version>.exe` |
| `packaging/qc.cmd` | The `qc` alias, installed beside `quickcode.exe` |
| `packaging/quickcode.ico` | The blue ghost app icon (16/32/48/64/256), generated by `scripts/make_icons.py` |
| `scripts/bootstrap.ps1` | Ensures Git + Python (>=3.12) are present. Used only by `install.ps1` now — the `.exe` installer no longer needs either. |
| `scripts/install.ps1` | Standalone local/dev installer for people who want a source/pipx install instead of the `.exe` |

## What ships in the install directory

| File | What it is |
|---|---|
| `QuickCodeApp.exe` | The windowed app. Start Menu, desktop shortcut, Explorer context menu. |
| `quickcode.exe` | The console CLI: `quickcode -p "..."`, `quickcode doctor`, `--version`, `qc .` |
| `qc.cmd` | Two-letter alias forwarding to `quickcode.exe` |
| `_internal\` | The Python runtime, the dependencies, `quickcode\frontend\`, and the package metadata |

The windowed executable is **not** called `QuickCode.exe`, and cannot be:
Windows file names are case-insensitive, so `QuickCode.exe` and
`quickcode.exe` would be one file in one directory — PyInstaller builds both
and silently overwrites the first with the second. The console name is the one
that had to survive verbatim, because it is the one a user types. The Start
Menu shortcut is still called "QuickCode"; nobody sees the executable's name.

## Building a release

`scripts/release.py --build` does all of this in order. By hand:

1. Install [Inno Setup](https://jrsoftware.org/isinfo.php) 6.1 or later (the
   script uses `WizardStyle=modern`).
2. Make sure the environment matches `pyproject.toml` — `uv sync`. The frozen
   build copies this environment's `quickcode` dist-info, so a stale editable
   install would ship the wrong version number to `--version`, `/api/health`
   and the update check. `release.py` refuses to freeze when the two disagree.
3. Freeze the app:

   ```powershell
   uv run --no-sync pyinstaller --noconfirm --clean quickcode.spec
   ```

4. Wrap it:

   ```powershell
   & "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe" /DMyAppVersion=2.2.0 packaging\quickcode.iss
   ```

The compiled installer is written to
`packaging\dist\QuickCode-Setup-<version>.exe`. Both that directory and
`dist\` and `build\` are gitignored.

If you changed the brand mark, regenerate the icons first — the `.iss` refers
to `packaging\quickcode.ico` for the wizard and the context menu, and
`quickcode.spec` embeds it in both executables:

```powershell
uv pip install pillow          # build-time only, not a project dependency
.venv\Scripts\python.exe scripts\make_icons.py
```

### What the installer does

- Installs **per-user** into `%LOCALAPPDATA%\Programs\QuickCode`
  (`PrivilegesRequired=lowest`), with an option in the elevation dialog to
  install for all users instead. That is the same directory the previous
  `{autopf}` install resolved to, so an upgrade lands in place.
- Copies `dist\QuickCode\*`, `qc.cmd`, the icon, `README.md`, `LICENSE` and
  `THIRD-PARTY-NOTICES.md`. That is the whole install — there is no post-install
  step and nothing is downloaded.
- Deletes `{app}\venv`, `{app}\src` and `{app}\scripts` first: leftovers from
  the pre-frozen installer, ~150 MB the new uninstaller would not know about.
- Offers three optional tasks:
  - **Add QuickCode to my PATH** (checked by default) — adds `{app}` itself,
    which is where `quickcode.exe` and `qc.cmd` are. The stale
    `{app}\venv\Scripts` entry from an older install is removed either way.
  - **Create a desktop shortcut** (unchecked by default).
  - **"Open QuickCode here" folder context menu** (unchecked by default) —
    `HKCU\Software\Classes\Directory\...` entries for both the folder and the
    folder-background right-click menus, running `QuickCodeApp.exe "%V"` on the
    clicked directory. `uninsdeletekey` removes them.
- Keeps the AppId `{6C8E6F2D-6E6A-4E6B-9C5A-2F5B1B8C6D3E}`. **Never change
  it**: Windows recognises an existing QuickCode install by that GUID, and a
  new one orphans every copy already out there.
- Leaves `%USERPROFILE%\.quickcode` alone on uninstall. That is the user's
  configuration, sessions and saved keys, not ours to delete.

Because the installer changes `PATH`, `ChangesEnvironment=yes` is set so
Explorer/new processes pick up the change without a reboot (already-open
terminals still need to be restarted).

## Option B: pip / uv, or a local dev install

The wheel and sdist are still built and still supported for anyone who already
has Python 3.12+; see the README. From a checkout:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install.ps1
```

By default this creates (or reuses) a `.venv` in the repo root and installs
QuickCode into it in editable mode. Useful flags:

- `-UsePipx` — install with [pipx](https://pypa.github.io/pipx/) instead,
  which puts `quickcode` on your user `PATH` globally rather than inside a
  project-local venv.
- `-Dev` — also install the `dev` extras (`pytest`, `ruff`, ...). Only
  applies to the `.venv` path.
- `-SkipDependencyCheck` — skip the Git/Python auto-install step (use when
  you already know both are present and want a faster run).

`install.ps1` calls `bootstrap.ps1` under the hood (in dependency-only mode,
`-SkipQuickCodeInstall`) for the Git/Python detection and silent-install logic.

## Entry points

| Command | Kind | Behaviour |
|---|---|---|
| `quickcode`, `qc` | console script / `quickcode.exe` | Starts the local server on 127.0.0.1 and opens the app window on the current directory. `qc .` and `qc C:\proj "prompt"` also work. |
| `quickcode-app` | GUI script (`pythonw`) / `QuickCodeApp.exe` | Same app with the user's home directory as the default project, launched without a console window. What the shortcuts run. A folder passed on the command line (the context menu's `%V`) wins over that default. |

## Notes

- All PowerShell here is written for **Windows PowerShell 5.1** (no `&&`/`||`
  chaining, no ternary/`??`/`?.` operators) since that's the default shell
  version shipped with Windows 11.
- The frozen build embeds a 64-bit Python runtime and CPython extension
  modules, so the installer is x64-only (`ArchitecturesAllowed=x64compatible`).
- Nothing in this directory is executed as part of building/testing QuickCode
  itself; it's purely the distribution path for end users.
